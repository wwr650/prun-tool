# PRUN 生产队列面板

一个 Chrome 扩展（MV3，无需油猴），往 APEX（Prosperous Universe）里注入一个生产队列面板：先在本地把配方、生产线、订单大小排好，再一次性落进游戏的生产队列，省掉一条条手动开对话框的活。

* 目录：`extension/`（`manifest.json` + `content.js`，v0.4.0，无构建步骤、无依赖、无第三方库）
* 匹配：`https://apex.prosperousuniverse.com/*`
* 外部数据：prunplanner 的公开配方接口（`api.prunplanner.org`，无需授权）
* 权限：只申请了 APEX 站点本身，不申请任何扩展 API 权限，也没有后台服务。配方走内容脚本里的普通 `fetch`，实测从 APEX 源直接 200，不需要跨域代理。
* 更新记录见 [CHANGELOG.md](CHANGELOG.md)。

---

## 安装

1. 下载或 clone 本仓库，保留 `extension/` 整个目录。
2. 地址栏打开 `chrome://extensions`，右上角开启 **开发者模式**。
3. 点 **加载已解压的扩展程序**，选中 `extension/` 目录本身（不是它的上一层）。
4. **把旧版油猴脚本删掉或停用**——两者用同一套 DOM id 和 localStorage 键，同时挂着面板会叠在一起。扩展启动时会检测并放弃注入，但只会保留先到的那一个。
5. 刷新 APEX 页面，视口右缘出现 ★ 侧边标签，点它开合面板；`Alt+Q` 同样有效。

从油猴脚本迁移不用重做数据：内容脚本读的是同一个页面源的 localStorage，队列、扫描结果、配方缓存都原样带过来。

面板拖动：按住标题栏拖。标题栏右侧 × 关闭。侧边标签始终留在右缘，面板在它左边展开，两者不重叠。

## 三个页签

### 配方

从 prunplanner 拉回来的静态配方表，按 **产物英文缩写 + 建筑** 两个条件筛（不做中文名搜索），每行「入队」把配方加进队列。配方表缓存 6 小时，点「刷新」强制重拉。

配方表里的 `time_ms` 和游戏显示的耗时不是一个口径（API 大约偏 1.52 倍），所以行上会标住口径，最终以游戏为准。

### 队列

上半部分是 **扫描生产线模板**：脚本依次打开每条生产线的「新建订单」对话框，读出 APEX 自己的模板列表、单件时长和这条线所在的星球代码，同时从 PROD 瓦片的标题行读出这个基地的**生产队列 id**（基地内部编码），读完立刻取消关闭，绝不提交。

每个基地都有自己的内部编码：点开基地 `FK-794B` 的生产力，窗口标题是 `WF bda98a38`，它的生产队列就是 `PROD bda98a38`。**实盘里这个码写在 PROD 瓦片的标题行上，一个基地的整条队列共用它**，瓦片里每条线的表头只有线名（`农场`、`钻井`），所以一条线的身份是「队列 id + 线名」两段。同一星球上可以有几个同名基地，光看线名会选错，所以**执行队列先用码锁定基地**：在所有打开的瓦片里按码找那个基地，找不到就明确报错（把页面上开着哪些 `PROD <码>` 一条条列出来），不会静默下进别的基地；锁定了基地再按线名挑这个基地里的哪条线。只有从没扫到码的老条目才退回纯按线名匹配。

**多颗星球的生产列表可以同时开在一个页面上执行，不用来回切星球**（v0.4.0）。把几颗星球的 PROD 窗口都摊开，插件就把它们全部当成可见范围：状态栏报成 `打开 3 个生产列表 · 星球 BS-531a / AJ-768a / OF-375b · PROD bda98a38 @BS-531a 水培农场（进行1/队列0/空4） ｜ PROD abe11c @OF-375b 矿场…`；队列行的生产线下拉列出所有瓦片上的线（选项取值是 `线名@队列id`，光靠线名不再唯一）；执行时条目里的队列 id 落在哪个瓦片就去哪个瓦片点「新建订单」；「读取当前队列」按瓦片分组打印；扫描模板也是一次把所有打开的瓦片都扫掉。**没打开的星球动不到**：那种条目会失败并写清楚「当前打开的生产列表：…（没有 PROD xxx；把那个窗口打开，或重扫一次模板拿最新的码）」。唯一例外是没有队列 id 的老条目（线=「自动」）——它们仍然只在**第一个可见瓦片**里挨个试线，绝不跨瓦片试，不然一不留神就把订单下进另一个基地。

队列 id → 星球码 单独登记在 `prun.lines.v1`，状态栏和导出文件名都按瓦片上的码现查。**切星球**时游戏只是把旧瓦片隐藏、节点还留在页面里，所以只认看得见的瓦片（v0.2.0 会一直读旧星球那个隐藏瓦片，导致扫描和顶部星球信息都不跟着换）；面板开着时开/关某个 PROD 窗口、或切星球，约 2.5 s 内的轮询会跟着重算顶部那行（指纹覆盖所有可见瓦片）。这条线上还没扫过星球码时明写「未扫描」，不拿上一颗星球冒充。

扫描是**整片替换**：先清空，模板列表只反映这次扫到的那几条线，不会越扫越多。现在「这次」= 页面上所有打开的瓦片，所以多星球同屏扫一遍就把它们全收进来；只想扫某一颗星球就把别的窗口关掉。跨星球排好的队列不受影响——线名、队列 id、大小都存在队列条目自己身上，星球码在登记表里也留着，所以换颗星球扫完再切回来，那条线照样认得、照样能执行（下单读的是游戏对话框里的实时模板，本来就不依赖这份列表）。

这一步不是可有可无的：钻井、采集这类抽取线的产物取决于星球资源，prunplanner 的配方表里 `inputs/outputs` 是空的，**只有扫描能给抽取线入队**。扫描结果同时用来把建筑缩写关联到具体生产线。

模板可按产物 ticker 和生产线筛，默认按生产线分组折叠，分组标题和行上会显示队列 id 与星球代码，例如 `水培农场 PROD bda98a38 @ BS-531a`。

下半部分是队列本体，**按工厂分组**：同一条生产线（队列 id + 线名）的条目归成一组，组头写成 `1. 水培农场 PROD bda98a38 @ BS-531a　3 条产物：1.MUS → 2.VEG → 3.BTA`，条目左边带组内序号。执行时**做完一家再做下一家**（不跨工厂轮转），同一家内部仍按组内顺序轮转。组头有 `↑ 整组 / ↓ 整组`，整组换位会把交叉排的条目归拢成连续；行内 `↑ ↓` 只在本厂内换位（越过中间夹着的别家条目）。还没定生产线的条目单独归成「未指定生产线」一组，从队列页的下拉里指定线就会自动归位。组内从上到下的顺序**就是这一家的生产次序**——续排靠它判断「线上最后一单排在计划第几条」，所以想先产什么就把什么放前面。

组下面每条一行：

| 字段 | 含义 |
| --- | --- |
| 参与执行（勾选框） | 不勾就跳过这条 |
| 生产线 | 具体线（下拉项写成 `线名 PROD 队列id @星球码`，列出的是**所有打开瓦片**上的线），或「自动」。有队列 id 时**先用 id 在所有打开的瓦片里锁定那个基地**，「自动」只在这个基地的线里挨个试，不会跨基地；没有 id 才退回按线名试第一个可见瓦片的线。同一基地里真出现重名线时按出现次序编号（`农场`、`农场#2`） |
| 大小 | 订单大小 1–20 |
| 重复填满 | 勾上后在本厂内按组内顺序轮转续填，**一直下到这条线实测无空位为止**（没有次数上限），见下节 |
| 降档 | 库存不足时自动把大小降到当前买得起的档 |
| ↑ ↓ 删 | 排序（只在本厂内换位）和删除 |

行下面两行纯文字：一行复述方案（线、大小、重复、降档、星球），一行算耗时——`单件时长 × 大小 = 一单 × N 单`。队列底部给两个总数：**串行相加**（所有选中订单首尾相接）和**按线并行**（取最长的那条线），因为同一线只能排队、不同线可以并行。

**导出JSON / 导入JSON** 走的是真实文件：导出下载 `星球代码_建筑_PROD队列id_日期时间.json`（跨星球、跨建筑或跨队列时名字里会写明），每条导出项带 `queueId`（`PROD bda98a38`）、`code` 和 `loc`，导入时把 `queueId` 反解回 `code` 并并进登记表，所以换浏览器导入也认得这些队列线。导入用文件选择器，会先校验再替换队列。队列本身也存在 localStorage，刷新页面不丢；重启恢复和导入走同一套字段补齐，只写了 `queueId` 的老档不会变成「界面上勾着参与执行、执行时却被跳过」。

队列列表上方有一个 **续排** 勾选框（`执行前读取线上队列，从最后一单之后续排`，默认勾上），开关即写入 `prun.resume.v1` 并在日志里回执；语义见「执行语义」。

队列最底部是 **「执行队列」** 按钮，排完队直接点就跑，**不弹任何确认**。按钮文字带当前档位（`执行队列（干跑）` / `执行队列（真实下单）`），档位由「执行」页的干跑开关决定，**默认不干跑**；真实下单时按钮转成警示色。执行期间按钮禁用并显示「执行中…」，重复点击会被忽略。

### 执行

这一页只管两件事：**是否干跑** 和 **日志**。

* **干跑**（默认不勾）：勾上后只走一遍完整流程（开对话框、选模板、设大小、检查闸门）然后取消，绝不提交。切换即生效并写入 localStorage（`prun.dryrun.v1`），队列页的按钮档位同步更新。
* 「读取当前队列」按瓦片分组打印：先一行 `【PROD 6d1d22c @OF-375b】`，再逐条线给进行中/排队数量和**空槽位数**（线用 `队列id(线名)` 报名）。只带 `data-prun-id` 的容器才算订单：队列没排满时游戏也会把剩余位置渲染成空容器（里面只有一个 `OrderTile__queue` 占位），把它们算进去数字会虚高。每条线最多列 8 单，其余汇总成「…还有 N 单未列出」。
* 「打开PROD」尝试替你点开生产列表瓦片。
* 日志文本框只读，「导出日志」下载 `prun-log_日期时间.txt`，「清空日志」清空。内存里最多保留最近 400 行。

## 执行语义

**一个工厂一个工厂做完**：执行按队列页的分组顺序推进，第 1 家全部下完才轮到第 2 家（以前的版本是所有勾选条目跨工厂轮转）。日志开头是 `=== 干跑/真实下单：2 个工厂 / 5 条，计划 N 单；工厂依次完成，组内按队列顺序轮转 ===`，每家一行 `【工厂 1/2】水培农场 PROD bda98a38 @ BS-531a：1.MUS → 2.VEG → 3.BTA`，每条下单前打 `[工厂1 第2轮 3/3] …`。

轮转而不是灌满：同一厂里的多条产物，**一轮里按组内顺序每条各下一单**，再进下一轮。比如一家厂里 MUS 和 VEG 都勾了重复，实际顺序是 MUS → VEG → MUS → VEG。

**重复填满没有次数上限了**（v0.3.0 一开始还有个 1–50 的「上限」输入框，已去掉）：勾了重复填满的条目，停止条件是**这条线实测无空位**——每轮开工前重新量一次该线的 `槽位容器总数 − 真订单数`，读到 0 就这一家收工；下单被游戏拒绝且证据是无空位时同样立即收工，不再去试这家剩下的条目（队列满是线的属性，不是某个产物的）。没勾重复填满的条目仍然是下一条一单。另有一道 60 轮兜底上限，只在页面上量不到槽位时才会碰到。

所以队列页底部那行总数只统计单次条目，勾了重复填满的会写成「N 条勾了重复填满，下到该线队列满为止，不计总时长」——它们要下几单取决于线上还剩多少空位，事先算不出来。

注意这跟 APEX 自带的「重复订单」单选框不是一回事——那个会让游戏无限重复这一张订单，所以脚本永远给它传 false。

**续排（默认开，队列页可关，`prun.resume.v1`）**：每家厂开工前先读这条线上已经排好的队列，拿**最后一单**的产物缩写回查它在组内计划里的位置，然后做两件事：**从它的下一条开始轮转**（命中的是最后一条就回到组首），以及把命中位置**及之前**的**单次条目**当成本轮已完成、这一轮不再下。你要的场景——PP2 按 `BDE,BTA,BSE,BBH,LBH,LDE,LSE,LTA` 排（每样一单），线上最后一个待生产是 `BTA`，插件就从 `BSE` 开始。日志会写清楚它是怎么认定的：`续排：线上最后一单 BTA（240单位 3天15小时，排队）= 计划第 2/8 条，从第 3 条 BSE 起续排`。计划里同一种产物出现多次时取**最后一次**的位置（那才是走得最远的一处）。判不出来的几种情况也都明说，一律从头开始：页面上没有打开的生产列表瓦片、这一组还没定生产线、打开的那些瓦片里没有这一组（提示「要续排先把那个 PROD 窗口开着」）、线上没有订单（附空槽位数）、线上最后一单的缩写不在这组计划里。如果这一组全是单次条目且都被位置判定吃掉了，就写「这一组的单次条目都已排在线上，跳过」。**勾了重复填满的条目不受位置判定影响**——它要下到队列满为止，位置只能决定从哪一条开始，不能替它决定还剩多少配额（v0.3.0 刚做出来时把两者混为一谈，导致多产物的厂子整组被跳过、一单都不下）。关掉续排就是每次从组里第一条开始排，用来在「线上排的东西跟计划没关系」的时候强制重排。

下单闸门：只有该线队列有空位、且仓储满足输入材料时才会点提交。买不起时如果勾了「降档」，自动降到能买的最大档；否则记明原因（缺哪种材料、需多少、仓储多少）并停止给这条续填，但不影响别的条目。真实执行中一旦报错就整体中止，避免继续误操作。

按钮是灰的、但输入材料没有缺口时，日志写 **「禁用原因未知」** 并把看到的原始证据打出来（输入行 / 成品行 / 提交按钮的 `disabled` 属性和 class，再加一句量出来的 `槽位 13/22` 或 `槽位 18/18（实测无空位）`），**不再猜「队列已满」**——抽取线（钻井 ` => H2O3`）根本没有输入行，那条猜测对这类线必然错。槽位数是「这条线的容器总数 − 真订单数」，游戏并没有把队列容量写在页面上，所以这是实测出来的观察值，只能当证据看，不是它声明的上限。

订单大小是拖 APEX 的滑块设进去的。`aria-valuenow` 会骗人（滑块自己动了、游戏状态没动），所以脚本按真实的 down → move → up 时间线拖，并且拿**表单自己渲染的「耗时」**回验。对不上就重试（重试时从轨道另一端拖满整程，只错开一格实测会被 rc-slider 吃掉），三次还不对直接拒绝下单。同理，模板点了没在表单上生效也会拒绝下单，不会把错配方塞进生产队列。

耗时校验比的是**两个区间的重叠**，不是"点是否落在区间内"：模板上那行单件耗时是被显示截断的（真实 34.9 小时只显示「1天10小时」），误差会随订单大小放大——大小 20 时最大差 20 小时，而总耗时自己的显示精度只有 1 小时。所以期望值取 `[单件 × 大小, (单件 + 显示档位) × 大小]` 这个区间，和表单耗时的区间求交集。早期版本按精确值比对，导致**大订单必然被误判成"滑块没生效"**（滑块其实已经设对了）。

## 性能

所有等待都是"轮询条件、到点就走"，不是盲睡固定毫秒。本地夹具实测：一次完整下单约 0.3–0.4 s，扫描 3 条生产线约 0.4 s（替换掉原先每单约 2.5 s 的固定等待）。实盘里 APEX 的渲染和往返比夹具慢，绝对值会高一些，但等待上限保持在旧版固定等待的量级，所以最坏情况不会明显变差。

跑队列时**把 APEX 标签页留在前台**。浏览器会把后台标签页的定时器压到 1 s 一跳，`requestAnimationFrame` 直接停摆，每一步都会明显变慢（脚本有兜底，不会卡死）。

## 已知限制

* 面板只按英文缩写搜，不认中文材料名（游戏的中文翻译是随对局数据下发的，离线拿不到）。
* 星球码只在打开下单对话框时才读得到：某条线的队列 id 从没扫成功过（比如刚切星球、还没重扫）时，状态栏对它写「未扫描」，不会拿别的星球冒充。
* 面板开着时切星球靠 2.5 s 一轮的瓦片指纹轮询发现，不是即时；急的话点一下「读取当前队列」或重扫。
* 表单的「位置」行是唯一明确标出这条线在哪个星球的地方，形如 `AJ-768 - Lemuria (AJ-768a)`；括号里的站点代码只有这里能稳定拿到。
* 队列 id 是按「一段纯十六进制」从瓦片标题行（`PROD cb05ba60`）剥出来的，表头自己带码（`水培农场 PROD bda98a38`）也照吃；`BS-BS-531a` 这类带连字符的站点码不会被误认。整串剥不到 id 时全部退回按线名匹配，行为和 v0.2.0 一致。
* 队列 id 是**整个基地共用**的，所以同一个基地里如果出现两条同名线，只能靠瓦片内的出现次序区分（`农场`、`农场#2`）。游戏若重排这些线，编号会跟着变——实盘里一个基地通常每种建筑只有一条线，真撞上再想办法。
* 多星球同屏执行的前提是**那个 PROD 窗口一直开着**：窗口一关，那条线就不在可见范围里了，执行会失败并报出当时开着哪些瓦片。反过来，一次开太多窗口时「线=自动、没有队列 id」的老条目只会在第一个可见瓦片里找线，找不到就是找不到，不会跑到别的瓦片去下。
* 依赖 APEX 的 CSS Modules 类名前缀（`TileFrame__`、`ProductionLine__`、`Window__` 等）和 DOM 结构，游戏改版可能需要跟着调整选择器。
* 改了 `content.js` 要在 `chrome://extensions` 点扩展卡片上的刷新，再刷新 APEX 页面才生效；只刷页面不会拿到新代码。
* 尺寸正确的真实提交已在 v0.2.0 实盘验证通过（2026-10-25）。轮转续填（勾「重复填满」多轮灌满）、按工厂依次执行 + 续排、抽取线的下单闸门都只在本地夹具上验证过，还没在实盘上下过一整队——续排读的是线上队列的**显示顺序**，实盘里那个顺序是否严格等于生产次序需要一份实盘日志确认。
* 耗时校验的区间宽度 = 单件显示档位 × 订单大小。单件耗时只显示到「天」的配方（≥1 天且不足 1 小时的部分被截掉）区间会宽到能容下相邻档位，此时只能靠滑块读数兜底。
* 抽取线（钻井等）下单按钮变灰时，如果表单里读不到输入行，脚本给不出原因，只能把成品行和按钮 class 打出来——需要按日志里的证据再判断到底是队列位、成品仓储还是别的闸门。

| `prun.recipes.v1` / `prun.recipes.at` | 配方缓存与时间戳（6 小时有效） |

| `prun.dryrun.v1` | 是否干跑（缺省 = 不干跑，真实下单） |
| `prun.resume.v1` | 是否续排（缺省 = 开，执行前先读线上队列） |
